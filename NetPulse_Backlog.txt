NetPulse – Candidate Backlog

Story 1 – Retrieve All Devices

Acceptance Criteria:
	1. API returns all registered devices.
	2. Each device has a unique ID.
	3. Device name must be included.
	4. Device status must be included.
	5. Successful request returns an appropriate success response.

Story 2 – Retrieve Device by ID

Acceptance Criteria:
	1. Valid device ID returns the matching device.
	2. Device ID, name, and status must be included.
	3. Unknown device ID returns a clear not-found response.
	4. Response format must be consistent.

Story 3 – View Active Alerts

Acceptance Criteria:
	1. API returns active alerts.
	2. Each alert includes an Alert ID.
	3. Each alert includes the associated device.
	4. Each alert includes severity.
	5. Each alert includes status.

Story 4 – Filter Alerts by Severity

Acceptance Criteria:
	1. API allows filtering alerts by severity.
	2. Only alerts matching the selected severity are returned.
	3. Invalid severity returns a clear error response.
	4. Response format must be consistent.

Story 5 – Acknowledge an Alert

Acceptance Criteria:
	1. API allows the user to acknowledge an alert.
	2. The correct alert is updated.
	3. Alert status changes to acknowledged.
	4. Invalid alert ID returns a clear not-found response.
